# Contributing / 贡献指南

## 简体中文

欢迎改进项目介绍、中英文翻译、指南、链接和展示素材。网站应用源码不在本仓库，网站功能问题可提交反馈供维护者处理。

### 提交反馈

先搜索现有 Issue，避免重复。Bug 请使用 [Bug 模板](https://github.com/BeatsAD/WenBin-AI-LAB-Showcase/issues/new?template=bug_report.yml)，功能建议请使用[功能建议模板](https://github.com/BeatsAD/WenBin-AI-LAB-Showcase/issues/new?template=feature_request.yml)。说明具体场景和期望结果，保持沟通友善、具体。

安全问题请按照 [SECURITY.md](./SECURITY.md) 私密报告，不要放在公开 Issue 或 PR 中。

### 提交 Pull Request

1. Fork 本仓库，从最新 `main` 创建一个主题明确的分支。
2. 让修改聚焦于一个问题，同步更新受影响的中英文说明、链接或图片说明。
3. 检查 Markdown 展示、相对链接和图片路径；新增截图注明来源日期与对应页面，并遮盖个人或客户数据。新增素材须具备公开分发权利。
4. 不要提交密钥、Cookie、私有源码、系统文件或本地工具配置。
5. 填写 PR 模板，说明原因、改动与实际执行的检查；涉及视觉展示时附预览。
6. 由维护者核查后通过 PR 合入 `main`。

本仓库没有应用构建或测试流程，文档修改无需安装 Node.js 或运行网站构建。修改 Issue 表单时需检查 YAML 语法及必填字段。提交贡献即表示你有权提交内容，并同意按本仓库 [MIT 许可证](./LICENSE)分发。

## English

Contributions to descriptions, English and Chinese translations, guides, links, and visual assets are welcome. The website application source is maintained elsewhere; website behavior can be reported here for maintainer triage.

### Give feedback

Search existing issues first. Use the [bug report form](https://github.com/BeatsAD/WenBin-AI-LAB-Showcase/issues/new?template=bug_report.yml) or [feature request form](https://github.com/BeatsAD/WenBin-AI-LAB-Showcase/issues/new?template=feature_request.yml). Describe the use case and desired outcome, and keep discussions respectful and specific.

Report security issues privately according to [SECURITY.md](./SECURITY.md); keep them out of public issues and pull requests.

### Submit a pull request

1. Fork the repository and create a focused branch from the latest `main`.
2. Keep each change focused. Update affected English and Chinese text, links, and image descriptions together.
3. Check Markdown presentation, relative links, and images. Include the source date and page for new screenshots and redact personal or customer data. Only contribute assets you may distribute publicly.
4. Exclude secrets, cookies, private source, system files, and local tool configuration.
5. Complete the PR template with motivation, changes, checks actually performed, and a preview for visual changes.
6. The maintainer checks contributions before merging them into `main` through a PR.

This repository has no application build or test pipeline. Documentation changes do not require Node.js or a website build. Changes to GitHub issue forms should include YAML syntax and required-field checks. By contributing, you confirm you have the right to submit the content and agree to distribute it under this repository's [MIT License](./LICENSE).
